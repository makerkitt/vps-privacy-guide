# 新 VPS 实机验证流程

目标：从一台新 VPS 开始，只按仓库文档完成部署。遇到缺失步骤先修正文档，再按修正后的步骤复验，让读者能重复同样的结果。

## 开始前需要的信息

- 新 VPS 的 SSH 别名，或 IP、用户名、端口和本机密钥路径。
- 服务器系统，以及是否已有其他业务。
- 实际使用的客户端系统、应用和版本。
- 使用域名证书还是公网 IP 证书。

密码在自己的终端交互输入，不写入聊天或仓库。实际配置和完整测试记录保存到被忽略的 `private/`。

## 执行顺序

1. 只读检查环境：对照 [服务器准备](buy-vps.md)，记录系统、架构、端口和网络情况。
2. 跟随 [部署教程](deployment.md) 启动 S-UI，检查回环管理入口、管理员凭据和数据持久化。
3. 按 [证书说明](tls.md) 完成真实证书签发与节点配置，逐条连接三种协议。
4. 按 [客户端说明](clients.md) 接入一台真实设备，明确哪些流量必须代理。
5. 按 [防泄露检查](leak-protection.md) 测试 DNS、IPv6、WebRTC、故障断线和网络切换。
6. 验证重启、备份恢复、证书续期和服务加载。
7. 使用干净的测试实例、快照或重新创建的测试配置复验修正过的步骤；不擅自重装用户服务器。

## 修正方式

每次遇到问题记录文档步骤、预期、实际、原因、修正和复验结果。现场执行的额外命令必须写回对应章节，不能只留在聊天记录里。客户端的实际菜单路径和配置在确认版本后补齐。

## 实测记录模板

| 项目 | 结果 |
| --- | --- |
| 测试日期、仓库提交 | 待实测 |
| VPS 系统、架构、机房 | 待实测；不公开完整 IP |
| S-UI / sing-box 版本 | 待实测 |
| 客户端系统、应用、版本 | 待实测 |
| Reality / AnyTLS / Hysteria2 | 分别记录通过或失败 |
| DNS / IPv6 / WebRTC | 分别记录通过或失败及测试方法 |
| 节点失效 / 进程退出 / 切网 | 分别记录是否意外直连 |
| 证书续期与加载 | 待实测 |
| 备份恢复与重启 | 待实测 |
| 文档修正后的复验 | 待实测 |

验收完成后只发布脱敏结果。任何一项未测或失败，都保留原状态，不用总体通过掩盖。
