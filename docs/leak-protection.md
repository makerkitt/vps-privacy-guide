# 连上以后，看看有没有漏 IP

先别急着把所有检查都做一遍。找一台你平时会用的手机或电脑，连上节点，从下面第一项开始。

这里说的“漏 IP”，是指你本来想让某些流量走代理，它却绕过去，直接从家里宽带或手机网络出去了。你主动设成直连的网站，看到本地 IP 是正常的。

> 这一页先把检查方法写出来。具体客户端里点哪个开关、填哪些配置，还要等我们拿真实设备测试后补齐。现在的客户端模板只用来测试节点，不能直接当作整台设备的防泄露配置。

## 先留一个对照

在没开代理的时候，记下自己网络的公网 IPv4；如果还有公网 IPv6，也一起记下。开代理后再比较，就容易分清哪个是服务器地址，哪个是本地地址。

完整地址留在自己的私有记录里。如果要把结果贴到 Issue，只需要说“出现了本地地址”，不用贴出具体 IP。

## 1. 看看是不是只开了系统代理

系统代理通常只管愿意使用它的软件。有的程序会自己联网，浏览器的部分功能也可能走不同的连接。

如果你希望更多流量一起经过代理，看看客户端有没有 **TUN** 或 **VPN 模式**。打开后，还要看哪些应用被排除了、哪些规则设成了直连，以及 UDP 有没有被接管。

这里容易误会的一点是：开关亮了，不代表所有流量都已经走进去。后面的检查还是要做。

## 2. 查网址时，有没有走回本地网络

DNS 可以理解成“查网址对应哪个地址”。网页访问走了代理，查地址这一步却可能还在用本地网络。

先检查客户端的 DNS 设置，再看看浏览器有没有自己设置安全 DNS。它们可能没有走同一条路。

测试时，出现的 DNS 服务应该和你的设置对得上。**DNS 的 IP 不一定等于 VPS 的 IP**，看到不一样的地址不用马上判定泄露；反过来，只看到国外的 DNS，也不能就算通过。

如果结果看不懂，先把客户端和浏览器的 DNS 设置记下来，再结合连接日志检查。DoH 只是加密了查询，并不说明这次查询一定经过了代理。

## 3. 别漏掉 IPv6

有时网页显示的 IPv4 已经是服务器地址，但电脑还在用本地 IPv6 直接联网。

如果测试里出现了运营商分配给你的公网 IPv6，这一项就还没配好。接下来检查客户端是否接管 IPv6；如果你的方案不走 IPv6，就需要在实际客户端或系统里阻止相关流量从它绕出去。

只把节点地址填成 IPv4，没有这个作用。也不用把测试中所有地址都当成泄露：局域网地址、链路本地地址和 mDNS 名称，与公网 IP 不是一回事。

## 4. 再看浏览器的 WebRTC

WebRTC 常用在浏览器通话里。它会通过 STUN 等方式了解自己的公网地址，所以可能出现“网页 IP 是服务器，通话连接却带出了本地 IP”的情况。

检查时，留意 WebRTC 结果里有没有你刚才记下的本地公网地址。如果有，先查 UDP 有没有经过代理，以及浏览器是否允许非代理的 UDP 连接。

有些浏览器可以限制这类连接。直接禁用 WebRTC 也可能影响通话功能，所以要按自己的用途选择；它也解决不了其他软件绕过代理的问题。

## 5. 故意让节点连不上，再试一次

我们希望的结果是：需要代理的流量停下来，而不是悄悄换成直连。

可以在一份临时客户端配置里，把节点端口改成一个不可达的端口，再测试。之后还要分别检查客户端退出、切换 Wi-Fi 和手机流量、休眠唤醒、重启设备时的表现。

不要为了做这个测试，把服务器的 SSH 或整台机器的网络关掉。先留好恢复办法，每次只改一处。

不同客户端的断线保护不一样，TUN 模式也不一定自带这个功能。如果节点坏了，网页反而通过本地网络打开了，就需要继续调整客户端或系统的阻断规则。

## 测完以后怎么记

不用写复杂的报告，把下面几项记清楚就够了：

| 检查什么 | 希望看到什么 |
| --- | --- |
| 指定走代理的网页 | 使用预期的服务器出口 |
| IPv6 | 按设置走代理或被阻断，没有从本地绕出去 |
| DNS | 查询路径符合自己的设置，没有意外回落到本地解析 |
| WebRTC | 没有出现本地公网 IP |
| 节点故障、客户端退出 | 需要代理的流量停下来，没有转为直连 |
| 切网、重启、唤醒 | 重新检查，结果仍符合上面的要求 |

记上测试日期、客户端版本和使用的网络。先把这一台设备测好，再换下一台。某次通过，不能代替换设备或升级后的检查。

还有一件事要分清：这些检查是在看流量有没有走错路。运营商仍能知道你连接了 VPS，VPS 服务商仍有你的账户信息，登录的网站也仍能认出你的账号。

想看技术细节，可以读 [sing-box TUN 文档](https://sing-box.sagernet.org/configuration/inbound/tun/) 和 [MDN 对 WebRTC、STUN 的解释](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Protocols)。
